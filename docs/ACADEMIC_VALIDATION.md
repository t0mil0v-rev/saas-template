# Академическая валидация

Название «академически выверенный шаблон» означает, что заявленные свойства
связаны с реализацией, тестом и воспроизводимой процедурой. Оно не означает
сертификацию продукта или отсутствие неизвестных уязвимостей.

## Полный drill

На чистом Linux-хосте с Docker выполните:

```bash
make academic-drill
```

Скрипт использует отдельный Compose project и отдельные тома. При существующем
`.env` он отказывается запускаться, чтобы не затронуть рабочую установку.

Проверка выполняет один связный сценарий:

1. Собирает и запускает production-образы с PostgreSQL, Redis и Caddy.
2. Поднимает Mailpit с обязательным STARTTLS и локальным тестовым CA.
3. Регистрирует пользователя и подтверждает получение письма через Mailpit API.
4. Создаёт контрольные данные, снимает backup штатным `backup.sh`, изменяет БД
   и восстанавливает её штатным `restore.sh`.
5. Проверяет значение после восстановления и фиксирует фактическое время.
6. Переключает Caddy на TLS, проверяет цепочку сертификата, HSTS и CSP.
7. Запускает k6: 5 виртуальных пользователей в течение 15 секунд, error rate
   меньше 1%, checks выше 99%, p95 ниже 750 мс.
8. Запускает OWASP ZAP baseline с пассивным анализом поднятого HTTP-контура.

Результаты остаются в `.academic-results`: `summary.json`, k6 summary, ZAP в
JSON/HTML/Markdown, TLS-проверки и логи Compose. GitHub workflow
`Academic validation` запускает тот же сценарий на каждом push в `main`, раз в
месяц и вручную.

## Что именно доказано

Успешный run доказывает, что текущие миграции, production-образы и скрипты
backup/restore совместимы между собой; SMTP-клиент действительно проходит
проверяемый STARTTLS; Caddy отдаёт ожидаемый TLS и security headers; базовая
нагрузка укладывается в зафиксированные пороги; пассивный DAST не обнаружил
ошибку уровня fail по правилам ZAP.

## Чего эта проверка не доказывает

- k6 smoke не определяет предельную производительность и размер production.
- Mailpit не проверяет репутацию домена, SPF, DKIM, DMARC и доставку реальному
  почтовому провайдеру.
- Локальный CA проверяет TLS-конфигурацию, но не публичный DNS и ACME renewal.
- ZAP baseline не заменяет authenticated active scan, ручную проверку бизнес-
  логики и независимый pentest перед значимым production-релизом.
- Restore drill использует текущую версию приложения. Миграция между разными
  релизами требует отдельной матрицы совместимости.

Поэтому термин применяется к шаблону и его инженерной доказательной базе, а не
к любому продукту, который будет построен поверх него.
